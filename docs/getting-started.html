Reading the Fleet Page

One page showing how 84 client sites across 6 hosts are actually doing — backups, WordPress versions, tracker leakage, mail authentication. It replaces the audit spreadsheet. Everything on it was measured by a script, not typed by a person.

First thing to know: it never touches a client site

Every tool feeding this page is read-only. Nothing updates a plugin, edits a file or changes a setting anywhere. It looks and it records. Applying fixes stays a human decision, made somewhere else.

So you can click anything on the page without consequence. The worst you can do is read a stale number.

Three cards, three separate questions

Each card answers one question, and a site gets a status on each independently. A site can be beautifully maintained and still leak trackers. Don't read one card's status as the site's overall grade — there isn't one.

FLEET HEALTH Is this site being maintained — backups, PHP, WordPress, plugins? CRIT 2 WARN 73 OK 4 + 3 skip, 1 frozen
COOKIE CONSENT Does the homepage fire trackers before anyone consents? WARN 48 OK 21 UNKNOWN 10 41 fire trackers before consent; 44 have no consent tooling at all. Never CRIT by design — CRIT stays a security tier so it remains a list somebody works through. These are technical observations, not legal conclusions.
EMAIL DNS Can this domain send mail that authenticates? SPF 72/78 DKIM 70/78 DMARC 78/78 Scored per domain, not per site, so it has no column in the big table at the bottom.

What the colours mean

Note that WARN is blue, not amber. The obvious green-and-amber pair failed colourblind separation when it was tested, so the page uses a validated set instead.

CRIT 2 act now
WARN 73 schedule it
OK 4 nothing pending that needs a person
SKIP 3 no environment to measure
FROZEN 1 site frozen by Pantheon

Statuses are worked out when the page is drawn, not when the scan ran. So retuning a threshold rescores every run in history at once, instead of looking like 84 sites changed overnight.

The one idea worth carrying away

Not knowing is never shown as a pass.

The failure this whole system is built against is a confident-looking value standing in for an absence — plugin_updates: 0 when nobody looked, up-to-date when the check timed out. That has happened, repeatedly, and almost every instance was caught by a person reading a page rather than by a test.

So coverage sits on the same screen as the answer. A green row is worth exactly as much as the coverage behind it, and the page tells you what that coverage is.

Why almost everything is WARN

Because 32 sites have been looked at but have no health evidence at all — no backup age, no plugin count, no theme count. They score WARN for that reason alone, not because anything is known to be wrong with them.

That 32 is the scoreboard. It is the number that measures whether this project is working, and watching it fall is what progress looks like. Most of it is sites on a host the scanner cannot reach yet. You can see exactly which ones by filtering the table at the bottom of the page to No health evidence.

Among the sites we can see: 42 are behind on WordPress core, 18 have a plugin backlog, 2 have no recent database backup, and 1 runs PHP past the end of security support.

Where a person is actually needed

  • Needs a decision lists 5 sites nobody has ruled on — no owner, no answer to whether they count as production. They are treated as production until someone decides, because guessing the other way once hid the worst-maintained site on the fleet.
  • Sites that do not reconcile shows sites appearing in one source but not another. Every one of those disagreements has turned out to be worth looking at.
  • What changed is the short list since each tool last ran — the part to read if you only read one section.
